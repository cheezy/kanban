# Stride Configuration

**Note:** Examples below use Unix/Linux/macOS bash syntax. Windows users should see https://github.com/cheezy/kanban/blob/main/docs/WINDOWS-SETUP.md for PowerShell equivalents.

Trunk-based, two developers on SEPARATE clones (one agent per clone — never two
agents in one working tree). Each task is built on its own branch and merged into
LOCAL main only after it is approved. Commits accumulate on local main and are
pushed to origin ONLY when a goal completes (after_goal), after rebasing the
whole goal's worth of commits onto the latest origin/main and re-testing.
Standalone tasks (no parent goal) merge to local main but are NOT auto-pushed —
push those manually.

**Why `after_doing` runs `mix test` and not `mix test --cover` (D223).** The
hook budget is per SECTION — wall clock across all of a section's commands, not
per command — and `after_doing`'s committed default is 120s.

With `--cover`, the section could never fit: `mix test --cover` measured **138s
on its own**, and the four gate commands totalled **152s**. The repo completed
tasks at all only because one machine carried an uncommitted
`STRIDE_HOOK_TIMEOUT_OVERRIDE=200` in `.claude/settings.local.json`. A fresh
clone could complete nothing.

Without it, measured as one campaign — three consecutive runs of the four gate
commands, with the override **unset** and enforced by `timeout 120`, so this is
the real committed budget rather than a simulation:

| Run | Section total | Result |
|---|---|---|
| 1 | 97s | fits |
| 2 | 89s | fits |
| 3 | 90s | fits |

**Worst observed 97s, so the margin is ~23s** — quote that, not the best run.
The band is 1.09× wide, which also answers the historical 1.7× spread seen while
`--cover` was in the gate: that variance did not survive removing it.

The gate still blocks. Re-verified after the change: with a deliberately failing
test planted, the same section returns **exit 2**.

**Coverage enforcement moved, and it is now slower.** Nothing local checks
coverage any more — `mix precommit` runs plain `test`, not `test --cover`, so
`after_goal` does not cover either. CI runs `mix test --cover` against the 90%
threshold on push to `main`/`release` and PRs to `main`
(`.github/workflows/elixir.yml`), and `deploy-review`/`deploy-prod` both
`needs: test`, so a coverage failure blocks deploy. But this repo pushes only at
`after_goal`, and standalone tasks never auto-push — so a coverage regression
can survive locally for a whole goal before CI ever sees it. That is a real
trade, not a free one.

**On raising the budget instead.** The *server* timeout cannot help:
`after_doing` is routed at the PRE phase, where no response payload exists yet,
so it always resolves to the local default
(`stride/hooks/stride-hook.sh:1280-1282`) — which makes
`lib/kanban/hooks.ex`'s `timeout: 120_000` inert for this path. The local
default in `default_budget_for_section()` (`:1252-1256`) *is* editable, up to
the 290s clamp at `:1294`, but that ships to every plugin user rather than
fixing this repo.

**Cold is a different story, and it is measured: the section takes 180s.** With
`_build/test` removed and the override unset, the same four commands took
**180s — 60s OVER the 120s budget**, because the first `mix test` pays a full
`MIX_ENV=test` compile that `before_doing`'s `mix deps.get` / `mix ecto.migrate`
(which compile `:dev`) do not pre-pay. Removing `--cover` is therefore
**necessary but not sufficient** for a fresh clone: it fixes the steady state,
not the first run. And a fresh clone would not get that far anyway — it must
clear `before_doing`'s own 60s budget first, with every dependency uncompiled.
The cold/first-run bootstrap is tracked as **D229**; it cannot be fixed inside
`after_doing` alone.

| Build state | Section total | 120s budget |
|---|---|---|
| Warm (worst of 3) | 97s | fits, ~23s margin |
| Cold (`_build/test` removed) | **180s** | **exceeds by 60s** |

Do not re-add `--cover` here without re-measuring the whole section.

## before_doing

```bash
git diff --quiet && git diff --cached --quiet || { echo "Working tree is dirty — commit or stash before claiming a task"; exit 1; }
git checkout main
git pull --rebase origin main || { git rebase --abort 2>/dev/null; echo "pull --rebase conflicted with local unpushed commits — resolve manually"; exit 1; }
mix deps.get
mix hex.outdated || { echo "Outdated dependencies — upgrade before claiming"; exit 1; }
mix deps.audit || { echo "Vulnerable dependencies — patch before claiming"; exit 1; }
mix hex.audit || { echo "Retired dependencies — replace before claiming"; exit 1; }
mix ecto.migrate
git checkout -B "$TASK_IDENTIFIER"
```

## after_doing

```bash
mix test
mix format --check-formatted
mix credo --strict
mix sobelow --config .sobelow-conf
git diff --quiet HEAD -- || (git add -A && git commit -m "Completed task $TASK_IDENTIFIER: $TASK_TITLE")
```

## before_review

```bash
git checkout main
git merge --ff-only "$TASK_IDENTIFIER" || { echo "main moved since branching — ff-only merge of $TASK_IDENTIFIER failed; resolve manually"; exit 1; }
git branch -d "$TASK_IDENTIFIER"
```

## after_goal

```bash
git checkout main
git fetch origin main
git rebase origin/main || { git rebase --abort 2>/dev/null; echo "rebase onto origin/main conflicted — resolve manually, then re-run after_goal"; exit 1; }
mix precommit
git push origin main
```
